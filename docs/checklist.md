## V1-d（1回目）: 設定モーダルと JSON入出力

**ここから実際に登録できます。** 初回は［設定］から部署 → 担当者の順に登録してください。

### 設定モーダル（CLAUDE.md 5.8）

- [ ] ［設定］を押すとモーダルが開く
- [ ] ［閉じる］ボタンと Esc キーで閉じられる
- [ ] 部署を追加できる（入力欄で Enter でも追加できる）
- [ ] 部署名を書き換えると、その場でガント側の見出しも変わる
- [ ] 部署の右に所属人数が出ている
- [ ] 担当者を追加できる（名前＋所属部署を選ぶ）
- [ ] 部署が1つも無いあいだは、担当者を追加できない状態になっている
- [ ] 担当者の名前・案件数・絵文字・一言コメントをその場で書き換えられる
- [ ] 書き換えるとすぐガントの担当者ヘッダに反映される（保存ボタンは無い）
- [ ] 案件数・絵文字・コメントは空のままでもよい
- [ ] 担当者の所属部署を変えると、ガント側の並びと部署の人数表示が両方変わる

### 削除の制約（CLAUDE.md 5.8）

- [ ] 担当者がいる部署を削除しようとすると、赤いメッセージで拒否される
- [ ] 担当者が0人の部署は、確認ダイアログのあと削除できる
- [ ] ある案件の唯一の担当者を削除しようとすると、案件名入りのメッセージで拒否される
- [ ] 複数担当の案件しか持たない担当者は、確認のあと削除できる（案件からは担当が外れる）

### 書き出し（CLAUDE.md 5.9）

- [ ] ［書き出し］を押すと `sgantt-backup-YYYYMMDD-HHMM.json` がダウンロードされる
- [ ] ダウンロードしたファイルをテキストエディタで開くと中身が読める

### 読み込み（CLAUDE.md 5.9）

- [ ] ［読み込み］でファイルを選ぶと「すべて置き換えます」と件数が出る
- [ ] ［キャンセル］すると何も変わらない
- [ ] ［OK］すると内容が置き換わり、画面も切り替わる
- [ ] **書き出したファイルを読み込むと、元どおりになる**
- [ ] 関係ないファイル（例: 適当なテキスト）を選ぶと、理由が出て**いまのデータは残る**

### まだ無い部分（想定どおり）

- [ ] 案件をクリックしても何も起きない（編集ポップアップは次回）
- [ ] 担当者ヘッダに「＋」ボタンが無い（新規案件追加は次回）
- [ ] 案件は画面から追加できない（次回の編集ポップアップと同時に入ります）

## V1-b: データ層

**画面の見た目は変わりません。** データを作る・直す・保存する仕組みだけを作った段階です。
目視で確かめられるものが無いため、代わりにテストで検証しています。

es さんの確認は次の1つだけです。

- [ ] ターミナルで下のコマンドを実行し、「すべて通りました。」と出る

```bash
node tests/store-test.js
```

### テストで確認している内容（157項目）

| 分類 | 主な確認内容 |
|---|---|
| 日付変換 | CLAUDE.md 4.1 の例（2020-01-01午前=0 など）、1200日ぶんの往復、夏時間のある地域でもずれないこと |
| 部署 | 追加・改名・削除、担当者がいる部署は削除できないこと |
| 担当者 | 追加・改名・絵文字・コメント・部署異動・削除、唯一の担当になっている案件があれば削除できないこと |
| 案件 | 新規追加（タイトル空・バー1本・ラフ/未着手/今日1日）、複数担当、非表示の切替 |
| 担当0名の拒否 | 担当者を0名にする操作が拒否され、拒否後もデータが元のまま残ること |
| バー | 工程・状態・期間の変更、入稿と納品が常に1日幅になること、一覧に無い工程・状態の拒否 |
| migrate | 省略された項目の補完、ずれたバーの丸め、壊れたJSON・矛盾したデータの拒否 |
| 入出力 | 書き出し→読み込みで内容が戻ること、ファイル名 `sgantt-backup-YYYYMMDD-HHMM.json` |
| 読み込み失敗 | 壊れたファイルを読ませても、いま入っているデータが消えないこと |

### 補足

- テスト自体が正しく働くかを確認するため、`store.js` の規則をわざと5か所壊して実行し、
  すべてテストが失敗することを確認しています（確認後、元に戻してあります）。
- V1-b の時点では画面から呼び出していないため、**入力したデータは画面には出ません**。
  実際に触れるようになるのは V1-c（表示）・V1-d（編集）です。
